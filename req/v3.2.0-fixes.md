# GMD 3.2.0 Review Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clear the eight findings from the 3.2.0 code review — two template-engine indentation bugs, a code-block output bug, a GgChart dimension asymmetry, a Gradle repository side effect, a misleading Gradle log message, a swallowed Maven interrupt, and a CLI path bug.

**Architecture:** Seven of the eight fixes are local and independent. The two template-engine fixes (Tasks 1 and 2) touch the same loop in `GmdTemplateEngine.processCodeBlocks` and must land in order. Both rest on the same new idea: **indentation is measured relative to the document's own base indent**, not absolutely. That is what lets GMD keep its existing leniency (a `.gmd` document written inside an indented Groovy triple-quoted string still works) while still honouring CommonMark's rule that a block indented four spaces *beyond the surrounding text* is literal.

**Tech Stack:** Java 21, Groovy 5.1.3, Maven 3.9.9+, Gradle 9.7.1, JUnit Jupiter 6.1.3, Jsoup 1.23.2, Mockito (maven-plugin tests), Gradle TestKit + ProjectBuilder (gradle-plugin tests).

**Spec:** This plan implements the findings recorded in the 3.2.0 code review; each task restates its finding in full, so no separate spec document is needed.

## Decisions already taken

These were settled before planning; do not relitigate them.

1. **Indented fences keep executing.** A ` ```{groovy} ` fence indented four or more spaces still runs. GMD's leniency here is load-bearing: `GmdTemplateEngineTest.testCodeOnly` and `testNoEcho` embed twelve-space-indented documents with no `stripIndent()`, and real users write `.gmd` inside indented Groovy strings. Task 1 therefore fixes only the *indent mismatch* the current code produces, not the execution itself.
2. **Known limitation, accepted:** because of (1), a `.gmd` document that tries to *show* GMD syntax by indenting it will still execute it. The documented workaround is a fenced block with a longer fence, which Task 1 leaves working. Task 1 records this in the method Javadoc.
3. **Gradle:** check for an existing Maven Central repository before calling `mavenCentral()`. The plugin still adds Central when the consumer has none.
4. **GgChart:** align on *always honouring the dimensions configured on the chart*, so only an explicit `width`/`height` argument overrides them.
5. **Echoed fences stay at column 0.** Task 1 makes the fence and its body agree by dedenting the body, not by re-emitting the fence at its original indent. Column 0 is always a valid fence position, so this can never turn the emitted ` ```groovy ` line into an indented code block. The cost, accepted here, is that a Groovy block written inside a list item is *not* kept inside that item: the emitted block breaks the list and the following item restarts as a new `<ol start="n">`. That is the behaviour today as well, so Task 1 neither fixes nor worsens it. Preserving list nesting would need the fence re-emitted at `min(indent, 3)`, the body dedented by the remainder, and the captured output indented to match - a wider change, out of scope for 3.2.0.

## Review Focus

Input classes these fixes imply but that no task's happy path exercises. Each has a test assigned to the task that owns the code.

1. **Tab-indented lines.** CommonMark counts a tab as four columns; the new indent helpers count spaces only, so a tab-indented literal block would still expand inline variables. → test in Task 2, pinning the documented space-only limitation.
2. **A uniformly indented document containing a genuinely indented literal block** (base indent + 4). Relative-indent classification must still protect it, or Task 2 only works for documents at column 0. → test in Task 2.
3. **CRLF input through the new indent helpers.** `readLines()` strips `\r`, but a whitespace-plus-`\r` line must still count as blank for paragraph tracking. → test in Task 2.
4. **A GgChart whose width/height were never set** (library defaults) printed with no arguments — must render at the library default, not 0×0 or NPE. → test in Task 4.
5. **A Gradle consumer that declared Central under its other host** (`repo1.maven.org` rather than `repo.maven.apache.org`), or with a trailing-slash difference. The URL check must recognise it, or Central is added twice. → test in Task 5.
6. **The first non-blank line defines the document base.** A stray column-0 line *after* an
   otherwise uniformly indented first block (an HTML block, a table row, a hard-wrapped line)
   must not collapse the base to 0 and silently stop later prose expanding inline variables.
   Conversely, if that column-0 line is the first non-blank line and the body sits eight spaces
   deeper, the body is classified as indented literal content and does not expand. That is the
   accepted invariant: authors must put the first non-blank line at the document's own indent.
   → the Task 2 test covers the later-stray-line case; the processCodeBlocks Javadoc records
   both directions.

```groovy
    /** Number of leading space characters. Tabs are not counted; see processCodeBlocks. */
    private static int leadingSpaces(String line) {
        int i = 0
        while (i < line.length() && line.charAt(i) == ' ') {
            i++
        }
        return i
    }

    /** Removes up to {@code width} leading spaces. Shorter indents are left untouched. */
    private static String dedent(String line, int width) {
        int i = 0
        while (i < width && i < line.length() && line.charAt(i) == ' ') {
            i++
        }
        return line.substring(i)
    }
```

### Task 2: Stop expanding inline variables inside indented literal blocks

**Finding #2.** The guard at line 115 only tracks *fenced* blocks (`plainFenceChar == null`), not indented ones, so CommonMark's indented code blocks are not protected:

```
Input:   "text\n\n    literal `= 1+1 ` here\n\nend\n"
Current: "text\n\n    literal 2 here\n\nend\n"
Wanted:  "text\n\n    literal `= 1+1 ` here\n\nend\n"
```

**Indent is measured relative to the document's base indent** — the indent of the document's first non-blank line (review round 3, finding F9). This is what keeps GMD's existing leniency: `GmdTemplateEngineTest.testInlineVars` embeds an eight-space-indented document with no `stripIndent()` and expects expansion, and every `GmdTest` fixture relies on `stripIndent()` producing base indent 0. Only a block indented four spaces *beyond its neighbours* is literal. Anchoring on the first line — rather than scanning for the smallest prose indent — means a stray column-0 line later in the document (an HTML block, a table row) cannot collapse the base and silently reclassify every other line (Review Focus 6). It is deliberately not a universal safeguard: if the first non-blank line is shallower than the body, that body is measured relative to the shallower base and may be classified as literal. Authors must put the first non-blank line at the document's own indent.

- [ ] **Step 3: Add the base-indent helper**

Add next to `leadingSpaces` in `GmdTemplateEngine.groovy`. The base indent is anchored on the
document's first non-blank line (review round 3, finding F9). Two benefits and one accepted
cost follow from that choice:

- A column-0 line *inside* a ` ```{groovy} ` block or a plain fence can never drag the base
  to 0 — the first line is never inside a block, and no later line is consulted. (A
  global-minimum scan needed a fence-tracking pre-pass for this; review F1.)
- A stray column-0 line later in the document — an HTML block, a table row, a hard-wrapped
  line — cannot collapse the base and silently reclassify every other line (Review Focus 6).
- The first non-blank line is the invariant, not a global minimum. If it is shallower than a
  body indented four or more spaces beyond it, that body is classified as literal and inline
  expansion is suppressed; authors must start the document at its own indent.

```groovy
    /**
     * The indent the document sits at: the indent of its first non-blank
     * line. Indented code blocks are recognised relative to this, so a .gmd
     * written inside an indented Groovy string behaves the same as one
     * written at column 0.
     *
     * Anchored on the first line deliberately: a global minimum could be
     * collapsed by a column-0 line inside a code block or a stray column-0
     * prose line (HTML block, table row), reclassifying the whole document.
     * The first line is therefore the invariant: when it is shallower than
     * the body, body lines four or more spaces beyond it are literal. Authors
     * must start a document at its own indent.
     * Lines before the first non-blank one are blank and say nothing; when
     * the document is entirely blank the base is 0.
     */
    private static int baseIndent(List<String> lines) {
        for (String line in lines) {
            if (!line.isBlank()) {
                return leadingSpaces(line)
            }
        }
        return 0
    }
```
