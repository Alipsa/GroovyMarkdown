# highlightjs-jvm

`highlightjs-jvm` exposes Highlight.js syntax highlighting to Java and Groovy applications
without a browser or JavaFX. It runs Highlight.js 11.7.0 on Rhino 1.9.1 - a single 1.6 MB
dependency - with all 192 upstream languages.

```java
SyntaxHighlighter highlighter = new HighlightJsHighlighter();
String html = highlighter.highlight("def answer = 42", "groovy");
```

`highlight` returns `null` when the language is null, blank or unknown to Highlight.js.
Callers should leave such code blocks alone. Auto-detection is deliberately not offered:
it mislabels prose and console output as code.

For HTML fragments or full documents, `HtmlSyntaxHighlighter` finds direct `pre > code`
blocks, preserves `nohighlight`, and inserts `hljs-*` spans while preserving the input
document shape.

## The runtime bundle

`src/main/resources/highlightJs/highlight.js` is generated by `./buildBundle.sh` from the
untouched Highlight.js distribution in `source/highlightJs`. The script concatenates, in
order: `src/main/js/prelude.js`, the upstream core, all 192 upstream grammars, and
`src/main/js/wrapper.js` - then runs a single stock `@babel/preset-env` pass over the result.

That pass transpiles **syntax only**. Rhino already provides `Symbol`, `Map`, `Set`,
`Object.assign`, arrow functions, template literals, destructuring, generators and optional
chaining, so **no polyfills are injected and nothing is hand-edited**. Rhino cannot parse
`class` declarations, rest parameters, call spread, `for(const...of)` or `\p{...}` regex,
which is the entire reason the transpile exists.

The toolchain is pinned by `package.json` and `package-lock.json` and installed with
`npm ci`, so the output is byte-reproducible. `./buildBundle.sh --verify` regenerates to a
temp file and diffs against the committed bundle, exiting non-zero if it is stale. Maven
never runs any of this, so a normal build needs no Node.

To upgrade Highlight.js, replace `source/highlightJs` with a newer `@highlightjs/cdn-assets`
release, run `./buildBundle.sh`, and commit the result.

## Threading and performance

Highlight.js keeps mutable state in the shared Rhino scope, so `HighlightJsHighlighter`
synchronizes; unsynchronized concurrent use was observed to corrupt that state. The Context
runs in interpreted mode, which avoids Rhino's 64K per-method bytecode limit on a ~1.2 MB
script. Measured on JDK 21 with all 192 grammars: engine init 182-287 ms warm, highlight
call 13-17 ms.
